# Research index

One line per finding, so a later session can decide what to open without reading each file.

- What Android gives a keyboard for voice input, and why a locale picker does not answer an accent complaint — an input method can recognise on-device from API 31 (forced from 33) with `RECORD_AUDIO`, proven by two existing keyboards, leaving API 26–30 uncovered; the selectable English set is organised by national variety and so reaches nobody whose accent comes from a first language; researched 2026-09-01 for `[in-keyboard-voice-input]`. android-voice-input-and-accents.md
- How much of a user's voice a speech model needs to adapt to them — the 30-minute figure applies only to full fine-tuning, which is the worst option at low data; LoRA adapts on minutes and beats it, embedding conditioning needs seconds, and one 2026 method needs no enrolment at all; gains are modest and measured on unrelated populations, and no Android implementation was found; researched 2026-09-01 for `[personal-voice-model]`. speaker-adaptation-cost.md
- Which word list predictive text can ship — SCOWL's licence is permissive enough for a public PolyForm Noncommercial repo and it separates proper names into an excludable category, but carries no frequencies; its size levels may serve as a proxy, otherwise Leipzig (CC BY) is cleaner than wordfreq (CC BY-SA), and `hermitdave/FrequencyWords` is a licence trap; researched 2026-09-01 for `[uniform-neighbours-predictive]`. word-list-licence-and-frequency.md
- Whether a horizontal pager can wrap Hexboard's board-level tap detector for panel switching — `detectTapGestures` consumes the pointer-down, so the obvious wrap is a known hazard; two workarounds named (a non-consuming tap detector, or parent drag detection in the Initial pass), neither tested because Gradle cannot run here; researched 2026-09-01 for `[panel-switch-gestures]`. compose-pager-vs-board-tap-gesture.md
- How Gboard corrects dictated speech, and what matching it would take — it is an all-neural RNN-T recogniser and there is no separate autocorrect stage, correction happening inside recognition with optional language-model rescoring of the N-best hypotheses, so a corrector on a finished transcript has strictly less to work with; Gboard also personalises from saved on-device transcripts of what the user says and corrects, which is in tension with this project's storage posture; whether the public on-device API is the same engine is unresolved and testable; researched 2026-09-02 for `[speech-output-correction]`. gboard-speech-correction.md
- Whether a Cyrillic alphabet fits Hexboard's board — SUPERSEDED the same day: its 30-slot budget was wrong (26 letter positions once the function keys are counted) and the pair-the-overflow rule fell with it, in favour of copying Gboard's eleven-column Russian keyboard; the ЙЦУКЕН row contents and Ё-under-Е still stand, the phonetic Russian layout never investigated; researched 2026-09-02 for `[language-starter-layouts]`. cyrillic-overflow-and-slot-budget.md
- Where to transcribe each language's phone keyboard layout from, hidden letters included — FlorisBoard's Apache-2.0 JSON layouts and per-language popup files, read directly: its Russian file is the 11-11-9 ЙЦУКЕН rows Gboard shows, and its popups put ё under е and ъ under ь; AOSP LatinIME carries the same under indirections, the GPL forks are avoided on licence; researched 2026-09-02 for `[language-starter-layouts]`. open-source-layout-sources.md
- Licence options weighed for a public Hexboard — what each licence permits about reading, forking for other languages, and contributing back; researched 2026-08-04 for `[licence-and-go-public]`. licence-options.md
