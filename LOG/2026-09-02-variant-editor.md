# [HASH] — The contributor-facing layout editor designed out in full and then deleted the same day, when copying each language's own standard replaced building a tool to author layouts

This is the entry the rest of the session's layout work cites, because the editor was designed properly before it was dropped and nothing about that design was wrong. What changed was the premise underneath it.

The item had been deferred four times. Three of its reasons died before today: the platform-versus-one-keyboard scope question was settled on 2026-08-20, the fork-sync problem dissolved when variants became contributions rather than forks, and the missing variant identifier closed when [variant-schema] shipped on 2026-09-01. So it designed out cleanly. Asked directly, the user settled that it builds a character set rather than rearranging an existing one — the prior art at `planning/hexboard-editor.html` only drags existing keys between slots, so this item's old line that "only its export is obsolete" understated the work. The user's own design for the opening screen was a choice of starter, bare board or a prepared language layout, then a rename; both single-starter options Claude had offered lost to it. Publishing was settled as a pull request into this repository, with a layout the maker keeps simply never submitted, and with submission as a valve that closes if review volume outgrows what one person wants to handle. Claude recommended the web page over an in-app editor and the user agreed, splitting the phone-side half into its own item.

Then the user reconsidered the premise, and the reconsideration was right. Their reasoning: an editor is a lot of machinery built for contributors who do not exist yet — the repository is not even public — while the layouts people actually want already exist as national standards, so copying them is cheaper and more likely to be correct than any tool for authoring them. Claude's one objection was to the word "automatically": generating a plausible Greek or Cyrillic layout is minutes of work and plausible is exactly the failure mode, because a shipped layout is copied rather than read. The user's answer dissolved that objection rather than overruling it — copy the published standard, which is a matter of record and can be checked against sources, instead of inventing anything. On that footing the editor had no remaining job, and the user directed that it and everything contradicting the new approach be removed: no personal layouts, no keyboard editor, just standard layouts.

What is deliberately not preserved, so nobody restores it as an oversight: the starter-choice screen, the rename-then-edit flow, personal layouts kept on the device, and creator attribution. Each was designed with the user and each died with the premise rather than by being judged badly. Git history holds the full text.
