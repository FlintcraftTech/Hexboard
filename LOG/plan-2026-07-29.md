# [HASH] — Migrate QUEUE to two-section model; settle two layout decisions and add a11y requirement

This planning session did two kinds of work. First, it migrated QUEUE.md from the old Sovereign Implementer format (Red flags / Batches / Deferred tests / Captures) to the current two-section model (Processed / Unprocessed with a cleared-to-run marker), because the queue predated the method recut. The header prose was re-copied verbatim from the current shipped /setup template rather than rewritten. All existing content was preserved; no items were lost.

Second, it processed four captured items. **Left-space relocation** was dropped: a symmetric col-2/col-7 space arrangement was previewed against the current asymmetric col-4/col-6, but the asymmetric layout looked better by eye, so no change was made. **Hit-test accessibility** was split — its design half became a SPEC requirement (each key must expose its own accessibility node, since accessibility services bypass raw-touch routing and so are a separate concern from the nearest-centre math), and its verification half became a `[user]` on-device test on the Pixel 6, held below the cleared line until an Android build exists. **Capitalisation** was decided: uppercase glyphs render at 0.92× the lowercase font size (scaling was chosen over both leaving it as-is and a more aggressive 0.74 that made caps look undersized); recorded in SPEC. A reusable layout-preview harness (`planning/layout-preview.html`) was built to make these visual calls against the real geometry, and captured as a standing planning fixture.
