# 987cb5c — Five emoji panels built on Unicode's own bundled list, licence read first

Written 2026-09-04 at 16:03.

Found by /rescan on 2026-09-02: SPEC had promised five emoji panels reached by a downward swipe throughout, and a grep of the Kotlin found no vertical swipe and no emoji panel anywhere — the "dies in SPEC" case the seeding rule exists for.

The question at its centre was answered on 2026-09-02. SPEC had said the emoji panels were "system-supplied content", and nobody had established what that could mean on Android. `androidx.emoji2:emoji2-emojipicker` supplies an up-to-date list, skin-tone variants and recents, but only through `EmojiPickerView` — a vertical scrolling grid with a category header — and its catalogue is internal, the library's declared public API being the view, an item class and the recent-emoji providers. So the platform's content arrives with the platform's interface or not at all, and SPEC's five-panel promise and its system-supplied promise could not both stand. The user chose to bundle Unicode's own list and keep Hexboard's panels: `emoji-test.txt` lists every emoji in CLDR display order and its own header describes it as data for keyboards, which gives the content without the interface. It is the same division SPEC already applies to layouts. Rejected: adopting `EmojiPickerView`, which is less work and gets skin tones and recents for nothing but replaces Hexboard's emoji surface with Google's; and a hand-written list like the prototype's 250 characters, which contradicts SPEC's own wording and goes stale with every Unicode release.

**The licence, which this item made a precondition and which had not been read.** The item's own "Rests on" flagged the Unicode Terms of Use as NOT read and made reading them the condition of bundling, this repository being public. They were read on 2026-09-04: the Unicode License v3 is permissive in the MIT mould — use, copy, modify, merge, publish, distribute and sell without restriction — on one condition, that the copyright and permission notice appear either with the file or in the associated documentation. README's Notices section is the cheaper limb and now carries the notice. Filed as `workshop/resources/research/unicode-data-file-licence.md` with its index line. The user gave explicit go-ahead to fetch the file before anything was downloaded.

**The panel arrangement, read from the reference rather than invented.** The item said to slice the parsed list into five panels "in the file's own order", which taken literally gives 756 emoji per panel on a board that holds fifty. The item also named `hexboard17.html` as its reference for the panel arrangement, and the prototype settles it: five panels of fifty on a ten-by-five grid, the middle panel home taking the first fifty, the two to its right the next hundred, and the two to its left the fourth and fifth fifty each reversed, so moving outward from home in either direction moves further down the list. Slots fill down each column before moving right. That is what the build did. The shortfall it implies — 250 reachable of 3,781 bundled — is a sentence SPEC does not carry, so it was filed as [emoji-panel-reach] rather than written, per the rule that a build never writes product truth.

The gesture collision the item expected did arrive by construction: the prototype's arrangement is a vertical track containing the horizontal one, so a `VerticalPager` now wraps the letter pager, and the pointer-consumption trap [panel-switch-gestures] solved on the horizontal axis is live again on the vertical. That is exactly what the new test's last case checks rather than assumes.

Deliberately not in this item: skin-tone variants and recently-used tracking, both of which the Jetpack picker would have supplied and which are their own work; and whether the row above the keys stays visible on the emoji panels, which is undesigned.

**Confirmed:** the licence permits this and the notice condition is satisfied; and the parse and distribution run against the bundled file here give 3,781 fully-qualified emoji, five panels of fifty, 250 distinct and none empty.

**Unconfirmed, transcribed from the tick:** everything on the device. `EmojiPanelsUiTest` is Android Studio's to run, and its last test is the one to watch — the pointer-consumption trap arrives again on the vertical axis, and a key press still committing under both pagers is checked rather than assumed.
