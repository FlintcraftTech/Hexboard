# [HASH] — RARE's row 2 moved to columns 0-9, making all three English panels ten wide

Written 2026-09-04 at 15:59.

Settled with the user on 2026-09-03, from measuring every panel in both layouts. English RARE ran rows 0 and 1 in columns 0-9 and row 2 in columns 1-10 — ten keys either way, the last row simply indented. That indent is what made the panel eleven wide, so its radius was solved by dividing the width by eleven while QWERTY and SYMBOLS divided by ten: RARE's keys were already about nine per cent smaller than QWERTY's on the layout that ships, and every swipe between them resized the keys. Nobody had noticed because nothing had drawn the board as a real keyboard until 2026-09-03.

The indent was not worth keeping. It came from `hexboard17.html`, whose own comment on that row reads that column 10 is visible on the half-snap: the prototype's board could half-snap sideways, so a key hanging past the right edge stayed reachable. Hexboard's board does not do that and nothing plans to, so the eleventh column was an artefact of a mechanism this project did not reproduce — and it cost the whole panel nine per cent of its key size.

This is not a change to the key inventory. All ten characters stay on RARE's row 2 in the same order and nothing moves between panels, which is why it is a config edit rather than Kotlin: SPEC keeps geometry in code and the key inventory in config, and a row's horizontal offset is the config's. SPEC says nothing about RARE's offset, so no sentence there goes wrong.

Refused: leaving it and letting [panel-key-size-consistency] shrink QWERTY and SYMBOLS to match, which would make the default panel of the default layout about nine per cent smaller to accommodate one indented row of maths symbols; and dropping a character to fit ten columns, which SPEC's manifest rules make a deliberate loss and which nothing needs, the row already holding exactly ten.

**Confirmed, transcribed from the tick:** every panel in `resources/key-layout.json` now reports a widest row of ten columns, RARE's row 2 still carries the same ten characters in the same order (™ … – — × ÷ ± ≠ ≤ ≥), and the manifest regenerated cleanly from the edited config with a one-line change.

**Not confirmed, and it is the thing to watch:** the zag keys on column parity, so shifting the whole row by one inverts which of its keys sit low. That is a visible change nobody has seen, and it is what to look at when this reaches the phone.
