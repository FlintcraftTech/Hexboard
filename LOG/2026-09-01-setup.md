Epoch 5 introduces `workshop/` — the folder for what a project works *with* rather than what it ships — and instructs that the whole of a project's root `resources/` folder moves inside it. **That instruction was not followed literally, and the departure is the substance of this session.** It assumes `resources/` holds only research and testing material. Here it does not: alongside `resources/research/` sit `key-layout.json` and `key-manifest.md`, which are the keyboard's key data. SPEC names that path as the canonical layout, `android/app/build.gradle.kts` copies the file into the app's assets from there, `KeyLayout.kt` and the validation test read it, `scripts/generate-key-manifest.py` writes to it, and the README links it twice. A literal move would have broken the Android build and left SPEC naming a path that no longer existed, in exchange for putting product data in a folder meant for working material.

So the split was put to the user with both options and a recommendation, and their decision was to move only `resources/research/`. That is what happened, via `git mv` so the licence-options note keeps its history rather than arriving as a new file. `resources/` retains the key data and every reference to it still resolves — checked by grep across the Kotlin, the Gradle script, the Python generator, SPEC and the README, which found nothing left pointing at the old research path. The one reference that did need repointing was in `.gitignore`, whose line ignoring the session-start payload sample named `resources/research/…`; it now names the new path. A `workshop/resources/research/index.md` was written at the same time, because the research folder had never had one and a finding with no index line is invisible to every later session — the folder had a write path and no read path.

The plugin-managed block in CLAUDE.md had drifted from the current template in two places: the marker comment's own wording, and the SPEC-editing rule, which now draws a sharper line than the one this project was carrying — SPEC changes during planning, never during a build, and a build that finds SPEC short of a sentence files a queue item rather than writing product truth itself.
