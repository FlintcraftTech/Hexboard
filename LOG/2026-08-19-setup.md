# 3791490 — Setup migration to plugin 1.20.0-test12, and the stale plugin-managed block in CLAUDE.md replaced with the current one

The session-start check reported the plugin had been updated since this project was last set up, so /setup ran as a migration. Almost nothing needed doing: the document format was already at epoch 3 from the migration of 2026-08-14, QUEUE.md was already on the two-section shape, and `.gitignore` already carried both the `INBOX/` and `.throughliner/` lines the newer version expects. The only scaffold change was the recorded plugin version, bumped from 1.20.0-test4 to 1.20.0-test12.

The substantive finding came from the retired-terms check, which reads the project's own CLAUDE.md for descriptions of method pieces that no longer exist. It found three: batches with Build/Test/Audit subheadings, a Deferred tests section, and `Parked:` headers. That check is written as report-only, on the reasoning that CLAUDE.md is the user's file and reconciling its wording would clobber what they wrote — so the finding was first reported as something for the user to change themselves.

That framing turned out to be wrong, and the correction is the useful part of this session. All three descriptions sat *inside* the plugin-managed block at the top of the file, between the markers that say the block is updated on /setup. So the text was never the user's wording at all: it was an old plugin block that the migration of 2026-08-14 should have refreshed and did not. Replacing it wholesale was the correct move, and the report-only rule was never in play. Worth noting for anyone reading this as a worked example — the retired-terms check tells you a term is stale but not whose text it is sitting in, and where a project's CLAUDE.md carries a managed block, that is the first thing to establish before deciding whether to report or replace.

The block now matches the current template. What changed inside it: the QUEUE.md description covers the Processed/Unprocessed shape, the cleared-to-run line and the flavor tags instead of batches and deferred tests; `/next` is described as working several cleared items back-to-back; `/rescan` appears for the first time; `INBOX/` is described for the first time; and the retired `Editor: Zettlr` and `Working mode: local` settings are gone, both replaced by a default of linking to files plus a session-opening offer to paste text inline. The Project rules section below the closing marker — the Hexboard-specific content — was not touched.

One process note against the run itself: the setup marker that tells the safety check this is a setup session was deleted before the CLAUDE.md edit was attempted, so the edit was refused as an out-of-scope planning write. The marker was restored and the edit went through. The procedure says to delete the marker when the run ends, and the run had not ended — the retired-terms report was still owed a decision.
